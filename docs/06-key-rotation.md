# §06 — Ротация ключа site-пира (без потери узла)

Смена ключевой пары узла требует согласованной правки ДВУХ сторон: приватный ключ на узле + публичный на хабе (в `awg0.conf` + реестр `/etc/awg-hub/peers/*.peer`). Рассинхрон = меш узла умирает; узел без входящих после этого не поднять. Поэтому — со страховкой.

## Золотое правило
Узел БЕЗ входящих: смену ключа на узле обкладывать **sleep-сторожем** (фоновый откат на старый ключ через 180с, если новый не поднял хендшейк). Хаб правится сразу следом, окно разрыва — секунды.

## Порядок (обкатано на hub53, v24)
1. **На узле:** `umask 077; awg genkey > /root/new.key; awg pubkey < /root/new.key` → показать НОВЫЙ public (приватный НЕ светить). Бэкап: `cp /etc/config/network /root/network.bak.$(date +%s)`.
2. **На узле:** сохранить старый privkey (`uci get ...private_key > /root/old.key`), поставить sleep-сторож (180с → откат на old.key при мёртвом хендшейке), затем `uci set private_key=<new>; uci commit; ifup`.
3. **На хабе (сразу следом):** бэкап `awg0.conf`; `sed` заменить старый pubkey на новый в секции пира; `awg syncconf awg0 <(awg-quick strip awg0)` — ГОРЯЧАЯ синхронизация БЕЗ разрыва других пиров (деревня/город не страдают).
4. **Проверка:** `awg show awg0 | grep -A4 <new-pub>` → свежий хендшейк; сквозной `ping`. Сторож сам вынесет `keep`, если ключ взлетел.
5. **Реестр хаба:** обновить pubkey в `/etc/awg-hub/peers/<node>.peer` (иначе health-check покажет «чужой ключ / нет в туннеле»).
6. **Уборка:** `shred -u` временные ключевые файлы на узле.

## Грабли (durable)
- `uci show network.<iface>` печатает **private_key** открытым текстом. При выводе секции интерфейса ВСЕГДА грепать в обход: `uci show network.<iface> | grep -vE 'private_key'`.
- `awg show awg0` после `syncconf` может показать УНАСЛЕДОВАННЫЙ старый хендшейк-таймстамп нового пира (~часы) — это переходный артефакт, пингани узел, обновится на свежий.
- health-check хаба (`awg-hub.sh` пункт 4) читает реестр `*.peer`, НЕ conf. Если реестр не обновить — «чужой ключ» висит, хотя туннель жив.
