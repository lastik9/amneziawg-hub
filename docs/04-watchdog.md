# §04 — Mesh Watchdog

Крон-страж, поднимающий меш узла при зависании обратного канала. Обязателен на **каждом** узле, у которого нет входящих (двойной NAT / whitelist): если меш завис, удалённо не войти — watchdog единственный, кто поднимет узел сам.

## Две версии (по типу транспорта)

| Файл | Для узла | Лесенка восстановления |
|---|---|---|
| `scripts/mesh-watchdog-village.sh` | **дорога A** (AWG-in-WSS через clash+wstunnel), напр. деревня `awg_hub52` | протух → `clash restart` → 90с → `wstunnel restart` → 90с → `reboot` |
| `scripts/mesh-watchdog-directudp.sh` | **direct-UDP** (AWG-пир смотрит прямо на публичный IP хаба, без clash в тракте), напр. hub53 | протух → `ifdown/ifup` awg → 90с → `reboot` |

Общие параметры обоих: `MAX_AGE=300` (хендшейк старше 5 мин = мёртв), `REBOOT_COOLDOWN=3600` (ребут не чаще 1/час), маркер кулдауна `/tmp/mesh-wd-last-reboot` (в tmpfs — чистится ребутом, кулдаун снимается после перезагрузки).

Единственный честный индикатор жив/мёртв — **возраст latest handshake**. `endpoint`/`transfer` залипают и врут «жив» (см. §ИНЦИДЕНТ v20).

## GUARD «кто я» (введён после инцидента v23)

Оба скрипта в шапке проверяют `awg show interfaces | head -1` против `EXPECT_IFACE`. Если живой интерфейс не тот — скрипт логирует `GUARD: … -> no-op` и выходит `exit 0`, **не трогая ничего**. Это предохранитель: даже если файл окажется не на своём узле, он физически не навредит.

## Установка на узел

1. Определить реальное имя AWG-интерфейса **на самом узле**: `awg show interfaces`.
   ⚠️ Имя kernel-устройства может НЕ совпадать с именем uci-секции (durable-грабли hub53). Брать имя из `awg show interfaces`, не из `uci show`.
2. Скопировать нужную версию в `/root/mesh-watchdog.sh` (для direct-UDP — подставить имя iface в `EXPECT_IFACE` и `IFACE` вместо `__SET_IFACE__`).
3. `chmod +x /root/mesh-watchdog.sh`
4. Проверить: `sh -n /root/mesh-watchdog.sh` (синтаксис) и `sh -x /root/mesh-watchdog.sh` на живом меше — трейс ДОЛЖЕН пройти guard и выйти `exit 0` на первой ветке, БЕЗ строк restart/ifdown.
5. Добавить в крон: `*/5 * * * * /root/mesh-watchdog.sh` (файл `/etc/crontabs/root`; проверять через `cat`, не `crontab -l`).
6. Здоровье: `logread -e mesh-wd` при живом меше — **пусто** = норма.

## ⚠️ ОГРАНИЧЕНИЕ — не тестировать по-боевому удалённо

Боевую ветку (рестарты + reboot) НЕЛЬЗЯ проверять удалённо искусственным обрывом — это тот же суицид, что watchdog призван лечить. Проверка боевой ветки — только с руками на узле. Пока доверяем `sh -x`-прогону на живом меше (тихий `exit 0`).

## Durable-урок инцидента v23 (почему этот файл в git)

Раньше watchdog жил ТОЛЬКО на диске узла — без версии, без бэкапа. Команда записи watchdog для одного узла была выполнена по ошибке в ssh-сессии другого узла (деревни): heredoc затёр деревенский watchdog чужой (direct-UDP) версией. На деревне интерфейс из чужого скрипта не существует → скрипт счёл меш мёртвым → пошёл в ifdown и к reboot. Поймали на воротах (`sh -x` показал ifdown на живом узле), разоружили (пустышка `exit 0`), убили живой процесс по PID до первого reboot. Ребута не случилось, меш не падал.

Два следствия, закодированные здесь:
- **Watchdog версионируется в git** — восстановление теперь = heredoc из этого репо, а не сборка по памяти.
- **GUARD «кто я»** в каждом скрипте + правило: любая команда ЗАПИСИ на узел начинается с преамбулы-guard
  `[ "$(awg show interfaces 2>/dev/null | head -1)" = "ОЖИДАЕМЫЙ_IFACE" ] || { echo ABORT; exit 0; }`
  чтобы heredoc не мог выполниться не на том узле.

## Развёртывания (журнал)

### hub53 — direct-UDP, `awg_hub53` (v24)

Watchdog развёрнут из `scripts/mesh-watchdog-directudp.sh` (`__SET_IFACE__` → `awg_hub53` в оба места). Крон `*/5` в `/etc/crontabs/root`, crond активен. Ступень 1 (self-heal прямого UDP: `ifdown/ifup`→90с→reboot, ≤1/час) — боевая. `sh -x`-ворота на живом меше прошли зелёно: guard не сработал, первая ветка `exit 0`, без ifdown/ifup/reboot.

**Снята ложная граблина из v23.** В v23 `awg show awg_hub53 latest-handshakes` вернул `No such device`, хотя `awg show` без аргумента показывал `interface: awg_hub53` — это было записано как возможное расхождение kernel-iface ↔ uci-секции. Эмпирически (v24) на hub53 расхождения **НЕТ**: имя `awg_hub53` совпадает во всех источниках — `uci`, `awg show interfaces`, `awg show`, `ip link` (`21: awg_hub53`), и адресный запрос `awg show awg_hub53 latest-handshakes` отвечает нормально. Тот `No such device` был **транзиентным**: iface моргнул (down) ровно в момент замера при переподключении меша. Практика «брать имя из `awg show interfaces`» остаётся верной, но конкретно hub53 расхождения имён не имеет.
